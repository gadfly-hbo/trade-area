# 商圈数据 ETL 复盘与推断基准

> 2026-09-26 整理。本文档沉淀 2026-09-24 ~ 09-26 商圈指标全量补齐战役的方法、基准与重跑剧本；
> 口径规则（正则层）见 `AGENTS.md`，逐轮判定留档见 `reports/_audit/`，空值审计史见 `reports/空值排查报告.md`。

## 一、结论快照

- **覆盖**：现役 8 指标（客流三档/3公里人口/品牌数/商用面积/车位/开业年）98%–99%；森马三大人群 99.7%（2398/2405）。
- **可评分**：2340/2405（97.3%，严格四因子交集；任一因子缺失不评分）。
- **overrides**：`data/overrides.json` 3833 项 / 1807 商圈，全部可溯源到 `_audit` 留档，随 git 版本化。
- **剩余空值**：约 280 条，为源报告占位残文/明确「不可引用」/无任何数量锚点的真缺失。

## 二、七轮提取流水线复盘

| 轮次 | 输入 | 方法 | 判定/补值 | 关键产出 |
|---|---|---|---|---|
| R1（chunk-*） | 有信号未提取 3541 条 | 按指标切片、喂相关行 | 1531 | 峰值=日峰值等语义规则定型 |
| R2（round2-*） | 剩余空值 1857 | 扩行重判 | 337 | 覆盖 max 值域放宽至 100 |
| R3（round3-*） | 897 商圈全维度 1488 条 | **按商圈整喂 13 维全文**（替代按指标切片，漏判显著下降） | 41 | 确认大量空值是源文真缺失 |
| R4（round4-*） | 1447 条 | 用户授权放开**语义推算**（÷365/累计÷天数/比值拆档/加总） | 336 | 推断值全部标 inferred |
| R5（round5-*） | 商用面积 402 | 商用口径优先、总建面退让标推断 | 363 | buildingArea 改商用面积口径 |
| 验算（verify-*） | 全部推断+疑点+抽样 1418 项 | 带源文重算+口径核对 | **fix 114 / drop 89 + force 删 38** | LLM 推断错误率约 8%；force 机制上线 |
| R6（round6-*） | 1353 条 | **行业基准推断**（见下表）+ 复核 122 | 801（复核 fix 48/drop 22） | 空值基本清零 |
| R7（round7-*） | 574 条 | 扫尾：品牌面积基准、年份区间中值 | 366 | 八指标 98%+ |
| 人群（crowd-*） | 132 商圈 | 客群结构语义映射推断 A/B/C | 396 | 三大人群 99.7% |

**过程中修掉的真 bug**（一致性扫描/验算发现，勿回退）：
1. 车位正则吞「停车6元/**小时**」「车位近千个，**1**小时免费」的数字（约 130 商圈错值）→ 坏词窗+禁跨量词+域过滤；
2. 「历史**年**峰值 2400 万」「单日峰值 3000–5000 **万元**」被当日客流 → 年锚/单位后随「元」硬拒；
3. 公司注册年当开业年（华宇 2002→2004）→「正式开业」优先；
4. 密度句连坐误杀（「常住人口 25–35 万、密度 2.5 万人/km²」）→ 守卫窗口裁到分句内。

## 三、推断基准表（basis='benchmark' 层）

第六/七轮对**源文无任何数字线索**的空值采用行业基准推算，全部标 `inferred:true` 并回标 `basis:'benchmark'`（2026-09-26 启发式回标 664 项，658 项落库）：

| 基准 | 公式 | 依据 | 回标条目 |
|---|---|---|---|
| 周末客流 | weekday × 1.3（带 1.2–1.5） | 购物中心周末/工作日客流比常见区间 | 87 |
| 节假日峰值 | weekday × 1.8（带 1.5–2.0）/ weekend × 1.4（带 1.3–1.6） | 节假日较常规日抬升倍数 | 22 |
| 工作日客流 | peak ÷ 1.8 反推 | 同上逆向 | 12 |
| 车位数 | 商用面积(万㎡) × 80 | 0.8 车位/100㎡ 配建基准 | 254 |
| 品牌数 | 商户数 × 0.6；或商用面积(万㎡) × 20 | 一牌多店折算；品牌密度基准 | 289 |
| 3公里人口 | 中心城区人口 × 0.35 | 3km 圈层占中心城区比（无法回标：区人口未入库） | — |

- 基准值的完整 prompt 留档：`reports/_audit/round6-*`、`round7-*`。
- 回标方法：值与公式精确吻合（客流 ±2%、面积 ±3%）即标。**注意**：文内明示「周末为工作日1.3倍」这类文本比值可能与基准碰撞被误标——误标方向是「更保守」，无数据危害。
- 调参入口：想收紧/放宽某一档，改 `_audit` prompt 模板重跑对应指标，或直接改 overrides 条目。

## 四、数据可信度三层与 `basis` 字段

| 层级 | 含义 | 数据表现 | 页面表现 |
|---|---|---|---|
| direct 文内直取 | 源文数字直接陈述/正则提取 | inferred 无标记 | 无标 |
| computed 文内推算 | 从源文数字推算（÷365/比值/加总），或报告自带[推断]标注 | inferred:true | ⚠ 推断 |
| benchmark 行业基准 | 源文无数字，按上表基准推算 | inferred:true + basis:'benchmark' | ⚠ 推断（将来可分色） |

- `types.ts ValueBasis`；`DistrictSummary.basis` 仅记录 benchmark 层（直取不记录，payload 精简）。
- UI 现状三种来源同显 ⚠；如需区分，InferredTag 可按 `basis` 换色（如灰⚠基准/黄⚠推断），改一处组件即可。

## 五、重跑剧本（data/raw 更新时）

1. **数据入库**：新 md 加入 `data/raw/`；若渠道清单更新，先 `./node_modules/.bin/tsx scripts/backfill-md.ts --apply` 回填评级（幂等）。
2. **重跑 ETL**：`npm run etl`，读取控制台的指标抽取率报告（与本文档快照对比看退化）。
3. **增量审计**：找出 index 中 overrides 无记录的**新商圈名** → 按 R6/R7 模板切块（40–60 商圈/块）跑 LLM 推断 → 过合理域校验（DOMAIN 表见合并脚本/历史）→ 写 overrides（新条目标 inferred，基准来源标 basis）。
4. **一致性扫描**：单调性（工作日≤周末≤峰值，注意「假期日均<周末」是合法例外）、分布离群（>中位×10 或 <中位/40）、量纲（客流≥100 万/日必错）→ 疑点交 LLM 带源文复核 → force 修正/删除。
5. **用户验收**：抽 5–10 家详情页对照源文（本轮经验：用户抽查每次都能抓到真问题）。
6. `npm test && npm run build` → commit + push。

**注意事项**：
- overrides 按**商圈名**键控：源文件改名会令对应条目静默失效（值回退到正则结果）；删除商圈会留孤儿条目（无副作用）。
- 评分是严格模式：新商圈缺任一因子则无评分，属预期行为。

## 六、跨项目方法论（可复用）

1. **正则打底、LLM 收长尾、验算兜底**：标准措辞正则解决大头，长尾 LLM 语义判定；LLM 推断有 ~8% 错误率（实测 fix 114/drop 127 / 1418 项），**没验算过的 LLM 提取不能直接用**。
2. **程序扫描与逐项验算缺一不可**：车位 bug（130 错值）是分布扫描抓的，逐项验算漏了；倍数用反、口径张冠李戴是验算抓的，扫描抓不到。
3. **域校验是防幻觉最后闸门**：所有 LLM 出值过合理域（客流<100 万/日、租金 0.1–100 元/㎡/天……），累计拒收越域值 17+。
4. **按商圈整喂全文优于按指标切片**：R3 改法后漏判明显下降（每商圈一次判定全部缺失指标）。
5. **「硬拒/软标」分层是核心框架**：错误口径（销售额当客流/全市口径/步行街口径）硬拒；估算口径（推断）软标记入库——让「宁缺毋滥」与「空值尽量少」两个矛盾诉求共存。
6. **用户抽查是最硬的验收线**：斜杠连接、单位继承、注册年当开业年、保守 null……全部来自用户截图抽查。
